## 一、检测发现的问题（P0 → P3）

### P0：旅游图 POI 全部丢失（内容丰富度核心 bug）
- **现象**：旅游图 7 个 circleMarker 图层（文化设施/博物馆/历史遗迹/自然景观/宗教场所/公园绿地/重点地标）坐标全空，只有 cluster_count 非零。
- **根因**：`GeneralizationEngine._generalize_pois` 聚合输出坐标为 **tuple**，而 `cleanup_service._remove_degenerate` 用 `isinstance(c, list)` 判断，tuple 被误判为"非法几何"，整层删除。
- **影响**：POI 从应有数量降为 0，地图失去主要信息层。

### P1：意图检测相关性偏差（用户可感知）
| 用户表述 | 修复前 | 修复后 |
|---|---|---|
| 我想看武汉的地形地势 | question（误判） | map_generation / terrain |
| 把地图上的道路改成红色 | map_generation（误判） | map_modification |
| 武汉哪里好玩？ | question ✓ | question ✓ |
| 生成武汉市的行政区域划分图 | basic（类型识别失败） | administrative |

- **根因 A**：`MAP_KEYWORDS` 缺"地形/地势/地貌/高程/等高线/山体阴影"→ 地形诉求被当普通提问。
- **根因 B**：`_is_modify_request` 要求 `not _is_map_request`，含"地图"二字的修改语句被压制。
- **根因 C**：`QUESTION_MARKERS` 缺"哪里/哪儿/什么地方/在哪"。
- **根因 D**：`MAP_TYPE_MAP` 缺"行政区域/区域划分/各区分布/区划图/分区图"表达。
- **根因 E**：`_detect_intent` 中 `is_map` 与 `is_modify` 同时命中时落入兜底返回 question。

### P2：QA 检查器误报
- **"长江缺失"误报**：数据源确有 10 条"长江"，但 B1 覆盖检查只匹配图层名、不匹配要素名，位于"河流水面"图层内的长江被误报缺失。
- **河流注记重复点**：水系注记层与线注记层对同一要素各放一次注记，A3 重复点 + G 碰撞双扣分。
- **字体粗细误当线宽**：textLabel 图层的 weight（400/600/700）被符号检查当作线宽，报"700px 超标"。

### P3：测试残留污染
- 排查过程生成的多轮测试图写入用户索引（`data/users/local/maps.json`）与 `data/maps.json` / `data/maps/`。**已全部清理**，用户原始索引完整恢复（含从归档目录恢复的 6 张旧图）。

## 二、代码修复清单（8 个文件 + 意图/常量）

| 文件 | 修复内容 |
|---|---|
| `backend/app/services/generalization/engine.py` | `_to_lonlat` / `_to_latlng` 统一返回 list（坐标形态源头防回归） |

| `backend/app/services/qa/completeness.py` | B1 覆盖检查同时匹配图层名 + 要素名 |
| `backend/app/services/cartography_validator.py` | 符号检查跳过 textLabel 图层 weight |
| `backend/app/services/qa/data_quality.py` | A3 几何检查跳过 textLabel 注记层 |
| `backend/app/services/qa/metrics.py` | 旅游主题预期关键词改为实际图层名 |
| `backend/app/services/agent_service.py` | MAP_KEYWORDS 补地形词；QUESTION_MARKERS 补疑问词；`_is_modify_request` 不再被"地图"二字压制；`_detect_intent` 修改优先 |
| `backend/app/core/constants.py` | MAP_TYPE_MAP 补行政区划类表达 |
